# Gulf Tax & Accounting Suite — نظام المحاسبة والامتثال الضريبي الخليجي

منتج Arab Templates لأصحاب الشركات ومكاتب المحاسبة في الخليج: فواتير إلكترونية
برمز QR معتمد، حاسبة صافي إقرار ضريبة القيمة المضافة، ماسح فواتير ذكي، ومساعد
ضريبي مع قناة تواصل مع المحاسب — كل ذلك في صفحة واحدة عربية (RTL) بلا أي مكتبة
جافاسكربت خارجية.

## المكوّنات

| الملف | الوظيفة |
|---|---|
| `index.html` | الواجهة كاملة في ملف واحد: خمسة تبويبات (الفواتير، الإقرار، الماسح، المساعد والمحاسب، الباقات) + نموذج طباعة A4، مع **CSS و JavaScript مدمجين داخله** (لا ملفات ستايل أو سكربت خارجية) |
| `einvoice.py` | محرك الفواتير: نسب الدول، حساب البنود والخصم، TLV ثم Base64، تجزئة SHA-256 |
| `ledger.py` | سجل مبيعات ومشتريات لكل حساب + ملخص الإقرار + رسائل المحاسب |
| `ocr.py` | استخراج بيانات الفاتورة من صورة: Tesseract عند توفره، ومحاكاة صريحة بدونه |
| `server.py` | خادم Flask يقدّم الملفات وكل نقاط الـAPI |
| `exchange_rates.json` | لقطة أسعار احتياطية عند انقطاع مصدر العملات |

## التشغيل

```bash
python -m pip install flask segno     # مرة واحدة (segno اختيارية لصورة QR)
python gulf_tax_template_pro/server.py                # http://127.0.0.1:5075
python gulf_tax_template_pro/server.py --port 5080 --open
```

## الميزات

### ١) الفواتير الإلكترونية المعتمدة

- دول مدعومة: السعودية ١٥٪ · الإمارات ٥٪ · عُمان ٥٪ · البحرين ١٠٪ · قطر والكويت ٠٪ (القالب جاهز عند التفعيل).
- نسب الضريبة تُملأ تلقائيًا من الدولة، ويمكن تعديلها يدويًا.
- بنود غير محدودة عمليًا (حتى ٢٠٠ بند): وصف، كمية، سعر، خصم٪، صافي، ضريبة، إجمالي.
- خيار «الأسعار تشمل الضريبة» يستخرج الصافي والضريبة من السعر الإجمالي.
- رمز QR بصيغة **ZATCA TLV — المرحلة الأولى**: خمس وسوم (اسم المورد، الرقم الضريبي،
  الطابع الزمني UTC، الإجمالي، الضريبة) ثم Base64 — وهي البنية نفسها التي تعتمدها
  FTA في الإمارات لحقول الفاتورة.
- تجزئة SHA-256 للفاتورة تُعرض للتدقيق، ورقم فاتورة تلقائي `INV-<الدولة>-<YYYYMMDD>-<رمز>`.
- معاينة طباعة A4 كاملة (شعار المورد، بيانات العميل، البنود، الإجماليات، QR، التجزئة) عبر زر «طباعة / PDF».
- «حفظ ثم إضافة للمبيعات» يودع الفاتورة في سجل الحساب لتظهر في حساب الإقرار.

### ٢) حاسبة صافي الإقرار الضريبي

- ضريبة المبيعات المحصّلة − ضريبة المشتريات المدفوعة = صافي المستحق للهيئة.
- أربع بطاقات: المبيعات، المشتريات، الصافي (مع الحالة)، آخر موعد تقديم.
- إن كانت المشتريات أعلى يظهر **رصيد دائن** للترحيل بدل رقم سالب مبهم.
- جدولان للسجل مع حذف أي صف فورًا (الحذف يحدّث الحساب).
- الفترات تُبنى حسب الدولة (شهرية، أو ربعية للإمارات) مع احتساب تاريخ الاستحقاق.

### ٣) ماسح الفواتير الذكي

- **صورة**: PNG/JPG/WEBP/GIF/BMP/TIFF/PDF حتى ٦ ميغابايت عبر سحب وإفلات أو اختيار ملف.
- **نص**: لصق محادثة واتساب أو ملف TXT/CSV (محرك `whatsapp_invoice_parser.py`).
- الحقول المستخرجة (المورد، التاريخ، الصافي، الضريبة، الإجمالي، الثقة) قابلة للتصحيح قبل
  «أضف إلى سجل المشتريات»، وكذلك إضافة كل نتائج المسح النصي دفعة واحدة.
- زر «اختبار ٥٠٠ فاتورة» يقيس الأداء والالتزام بسعة الباقة.

### ٤) المساعد الضريبي والمحاسب

- مساعد قائم على قواعد معرفة خليجية (نسب، مواعيد، حقول الفاتورة، الغرامات، المسح، العملات).
- نموذج «التواصل مع المحاسب» ينشئ تذكرة برقم `GT-XXXXXX` ويحفظ الرسالة في سجل الحساب.
- شريط أسعار العملات الحية ولقطة احتياطية، ولوحة أخبار السوق والامتثال — كما كانت.

### ٥) إرسال الفواتير بالبريد — SMTP2GO

- قسم كامل في نافذة الإعدادات (⚙) بالعربية والإنجليزية: حالة الربط، اسم وبريد المُرسل، بريد الرد، وزر «تسجيل سريع في SMTP2GO».
- زر التسجيل يفتح رابط الإحالة من المتغير `SMTP2GO_AFFILIATE_LINK` (قابل للتغيير بلا لمس الكود).
- زر «إرسال بالبريد» في تبويب الفواتير يسلّم الفاتورة (HTML + نص بديل) بعملة الفاتورة القانونية عبر واجهة SMTP2GO الرسمية `POST /v3/email/send` باستعمال مكتبة بايثون القياسية.
- المفتاح `SMTP2GO_API_KEY` يُقرأ من بيئة الخادم أو من `.env` المحلي (غير المتتبَّع)، ولا يُعاد إلى المتصفح ولا يُطبع في السجلات. بدون المفتاح ترد الواجهة برسالة ثنائية اللغة وزر تسجيل، لا بخطأ صامت.
- «اختبار الاتصال» يرسل رسالة تجريبية إلى بريد المُرسل نفسه للتأكد من توثيق النطاق.

```env
# .env في جذر arab-templates (مستثنى من Git)
SMTP2GO_API_KEY=ضع_المفتاح_هنا
SMTP2GO_SENDER=billing@your-office.com
SMTP2GO_SENDER_NAME=مكتبك للمحاسبة
SMTP2GO_AFFILIATE_LINK=https://www.smtp2go.com/?via=arab-templates
```

- دليل الخطوات الكامل للعميل: [`../customer_guides/smtp2go_email_setup.md`](../customer_guides/smtp2go_email_setup.md).

## الواجهة البرمجية

| المسار | الوظيفة |
|---|---|
| `GET /` | الصفحة (المحتوى والتنسيق والسكربت داخلها) |
| `GET /api/health` | حالة الخادم والمحرك |
| `GET /api/countries` | الدول، النسب، العملات، الدوريات، الفترات |
| `POST /api/einvoice` | إصدار فاتورة (تحقق + حسابات + QR + تجزئة)، و`save:true` يحفظها |
| `GET /api/ledger` | سجل المبيعات والمشتريات |
| `POST /api/ledger` | إضافة صفوف مشتريات (`rows[...]`, `source`) |
| `DELETE /api/ledger/<kind>/<id>?account=` | حذف صف |
| `GET /api/taxreturn?account=&country=&period=` | ملخص الإقرار |
| `POST /api/ocr` | صورة فاتورة → حقول مستخرجة (`save=1` يحفظها) |
| `GET/POST /api/support` | رسائل المحاسب والتذاكر |
| `POST /api/scan` | مسح نص أو ملف TXT/CSV |
| `POST /api/assistant` | المساعد الضريبي |
| `GET /api/plans` · `/api/quota` · `/api/news` · `/api/rates` · `/api/sample` | الباقات والسعة والأخبار والعملات والنموذج |
| `GET /api/email/config` | حالة ربط SMTP2GO، رابط الإحالة، وبريد المُرسل الافتراضي (بلا مفتاح) |
| `POST /api/email/send` | إرسال فاتورة أو رسالة اختبار عبر SMTP2GO (`to`, `sender`, `invoice`, `test`) |

## التخزين

`reports/gulf/<account>.json` لكل حساب: `sales` و`purchases` و`messages`، ولا يحتوي أي
سر أو توكن. لا يُخزَّن نص فاتورة خام ولا صور؛ تُحفظ الحقول المستخرجة فقط.

## حدود معروفة

- **OCR**: هذا الجهاز لا يحتوي Tesseract، فالماسح يعمل في **وضع محاكاة** يوضّح ذلك في
  الواجهة والاستجابة (`mode: "simulation"`)، ويستخرج قيمًا متسقة من بصمة الصورة نفسها.
  ثبّت Tesseract مع حزمة اللغة العربية فيتحول تلقائيًا إلى `mode: "tesseract"` ويقرأ
  النص فعليًا ثم يمرّره إلى المحلل نفسه.
- **QR**: يستخدم `segno` (بايثون، بلا تبعيات). بدونها تُعرض الحمولة النصية فقط مع تنبيه.
- **الفاتورة**: المرحلة الأولى من ZATCA (TLV + QR). التوقيع الإلكتروني وCSID وختم
  المرحلة الثانية يتطلبان شهادة من الهيئة وربطًا رسميًا — خارج نطاق هذه النسخة.
- **الإقرار**: حساب إرشادي للمبالغ؛ لا يُقدَّم نيابةً عنك إلى بوابة الهيئة.
- **المحاسب**: الرد فوري آلي ويُحفظ كتذكرة محلية؛ لا يوجد طرف بشري متصل.
- **البريد**: الإرسال يحتاج حساب SMTP2GO ونطاقًا موثقًا (`SMTP2GO_API_KEY`). بدون المفتاح يظل زر الإرسال موجودًا لكنه يشرح الخطوة المطلوبة بدل الإرسال.

## الأمان

- لا أسرار ولا مفاتيح في هذه الملفات، ولا اتصال ببابل من الواجهة.
- كل مدخلات النماذج تتحقق على الخادم (أسماء، رقم ضريبي، كميات، خصم ٠–١٠٠، تواريخ).
- حدود الحجم مفعّلة: ٨ ميغابايت للطلب، ٦ للصورة، ٨٠٠ ألف حرف للمسح النصي، ٥٠٠ صف لكل إضافة.
- مفتاح SMTP2GO يبقى على الخادم فقط، ويُتحقق من بريد المستلم والمُرسل قبل أي نداء خارجي.

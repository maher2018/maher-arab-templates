# ربط البريد عبر SMTP2GO — القالب الضريبي الخليجي

هذا الدليل يشرح ربط حساب **SMTP2GO** بالقالب الضريبي في `gulf_tax_template_pro`، حتى تُرسل الفواتير إلى عملائك من بريد نطاقك الموثق، بدل الطباعة أو التصدير اليدوي.

> **النتيجة المتوقعة:** زر «إرسال بالبريد» في تبويب الفواتير يسلّم الفاتورة (HTML + نص بديل) إلى بريد العميل، ويظهر في إعداداتك حالة «SMTP2GO مربوط — الإرسال جاهز».

---

## ١) أنشئ حساب SMTP2GO

1. افتح القالب الضريبي، ثم اضغط زر **⚙ الإعدادات** في الشريط العلوي.
2. في قسم **«إعدادات إرسال الفواتير بالبريد — SMTP2GO»** اضغط **«تسجيل سريع في SMTP2GO»**.
   - الزر يفتح رابط الإحالة المضبوط في المتغير `SMTP2GO_AFFILIATE_LINK`، ويُفتح في تبويب جديد.
3. أكمل التسجيل في SMTP2GO وأنشئ الحساب.
4. من لوحة SMTP2GO: **Sending → Sender Domains** وأضف نطاقك (مثال `your-office.com`)، ثم أضف سجلات DNS التي يعرضها (SPF و DKIM و CNAME) عند مزود النطاق.
5. انتظر حتى تصبح حالة النطاق **Verified**. بدون هذه الخطوة سيُرفض الإرسال من بريدك.

**بديل أسرع للتجربة:** يمكن توثيق بريد واحد (Single Sender) بدل النطاق كاملًا، لكن الإرسال للعملاء من نطاق موثق أفضل لوصول الرسائل.

---

## ٢) أنشئ مفتاح API

1. من لوحة SMTP2GO: **Sending → API Keys → Add API Key**.
2. الاسم: `Arab Templates — Gulf Tax`.
3. الصلاحية: **Email send** فقط (لا تمنح صلاحيات إدارة إضافية).
4. انسخ المفتاح فورًا؛ لن يظهر كاملًا مرة أخرى.

---

## ٣) ضع المفتاح على الخادم (لا في المتصفح)

القالب يقرأ الإعدادات من متغيرات البيئة، ويقرأ أيضًا ملف `.env` المحلي إن وُجد (وهو مستثنى من Git في هذا المستودع).

أنشئ أو عدّل الملف `arab-templates/.env` وأضف:

```env
# SMTP2GO — إرسال الفواتير بالبريد
SMTP2GO_API_KEY=ضع_مفتاح_API_هنا
SMTP2GO_SENDER=billing@your-office.com
SMTP2GO_SENDER_NAME=مكتبك للمحاسبة
SMTP2GO_AFFILIATE_LINK=https://www.smtp2go.com/?via=arab-templates
```

| المتغير | إلزامي | الوظيفة |
|---|---|---|
| `SMTP2GO_API_KEY` | نعم | مفتاح الإرسال. وجوده هو ما يجعل الحالة «مربوط». |
| `SMTP2GO_SENDER` | مُستحسن | بريد المُرسل الافتراضي الموثق في SMTP2GO. |
| `SMTP2GO_SENDER_NAME` | لا | الاسم الظاهر للمُرسل (افتراضي: Arab Templates). |
| `SMTP2GO_AFFILIATE_LINK` | لا | رابط زر التسجيل السريع. استبدله برابط إحالتك الخاص. |

> ⚠️ لا تضع المفتاح في `app.js` أو `index.html` أو أي ملف متتبَّع في Git. الواجهة تستقبل حالة الربط فقط، ولا يُعاد المفتاح إلى المتصفح أبدًا.

بعد الحفظ أعد تشغيل الخادم:

```bash
python gulf_tax_template_pro/server.py --port 5075
```

## ٤) أكمل الإعدادات في الواجهة

1. افتح **⚙ الإعدادات**.
2. املأ:
   - **اسم المُرسل** — يظهر في صندوق الوارد للعميل.
   - **بريد المُرسل الموثق** — نفس بريد `SMTP2GO_SENDER`.
   - **بريد الرد (Reply-To)** — اختياري، ليصل رد العميل إلى محاسبك.
3. اضغط **«اختبار الاتصال»**: يُرسل SMTP2GO رسالة اختبار إلى بريد المُرسل، وتظهر نتيجة الإرسال أسفل القسم.
4. تُحفظ هذه الحقول في متصفحك (`at_gulf_email`) وليست أسرارًا.

حالات الحالة (Status) في القسم:

| الحالة | المعنى | الحل |
|---|---|---|
| 🟢 SMTP2GO مربوط — الإرسال جاهز | الخادم يجد `SMTP2GO_API_KEY` | جاهز للإرسال |
| 🔴 SMTP2GO غير مربوط | لا يوجد مفتاح في بيئة الخادم | أضف المتغير وأعد التشغيل |
| جارٍ التحقق… | لم يصل رد `/api/email/config` | تحقق من تشغيل الخادم |

---

## ٥) أرسل فاتورة بالبريد

1. في تبويب **الفواتير الإلكترونية**: أدخل بيانات المورد والعميل، وأضف **بريد العميل** في حقل «البريد».
2. أصدر الفاتورة (زر «إصدار الفاتورة ورمز QR»).
3. اضغط **«إرسال بالبريد»**.
4. يصل العميل: عنوان الفاتورة، بيانات المورد والرقم الضريبي، البنود والإجماليات بعملة الفاتورة القانونية، حمولة QR وتجزئة الفاتورة.

> الفاتورة تبقى دائمًا بعملة الدولة القانونية حتى لو كانت واجهتك تعرض مبالغ الإقرار بعملة أخرى.

## ٦) استكشاف الأخطاء

| الرسالة | السبب | الحل |
|---|---|---|
| «حساب SMTP2GO غير مربوط بعد…» | لا يوجد `SMTP2GO_API_KEY` في بيئة الخادم | أضف المفتاح في `.env` ثم أعد تشغيل الخادم |
| «أدخل بريد العميل في نموذج الفاتورة أولًا» | حقل بريد العميل فارغ | أضف البريد ثم أعد المحاولة |
| «بريد المُرسل غير صالح — استخدم بريدًا موثقًا» | بريد المُرسل ناقص أو غير موثق | وثّق البريد/النطاق في SMTP2GO وضع البريد نفسه هنا |
| «رفض SMTP2GO الطلب: …» | مفتاح خاطئ، نطاق غير موثق، أو تجاوز الحصة | راجع API Keys وحالة النطاق واستهلاك الحصة |
| «تعذّر الوصول إلى SMTP2GO» | شبكة/جدار ناري يمنع `api.smtp2go.com` | اسمح بالاتصال الصادر HTTPS (443) |
| الرسالة لا تصل | مجلد المهملات أو SPF/DKIM ناقص | أكمل سجلات DNS واطلب من العميل إضافة المُرسل للقائمة الآمنة |

فحص سريع بدون واجهة:

```bash
curl -s http://127.0.0.1:5075/api/email/config
# {"provider":"smtp2go","configured":true,"affiliate_link":"…","env_var":"SMTP2GO_API_KEY", …}
```

## ٧) ملاحظات أمان وتشغيل

- المفتاح يُقرأ على الخادم فقط، ولا يُسجَّل في السجلات ولا يُعاد في أي استجابة.
- التكامل يستخدم واجهة SMTP2GO الرسمية `https://api.smtp2go.com/v3/email/send` بمكتبة بايثون القياسية (بلا حزم إضافية).
- احتفظ بسجل الفواتير المرسلة: الحفظ في سجل المبيعات يبقى خطوة منفصلة عن الإرسال بالبريد.
- لتدوير المفتاح: أنشئ مفتاحًا جديدًا في SMTP2GO، حدّث `.env`، أعد تشغيل الخادم، ثم احذف القديم.

## English summary

1. Open the template, press **⚙ Settings**, then **Quick SMTP2GO signup** (uses `SMTP2GO_AFFILIATE_LINK`).
2. In SMTP2GO verify your sender domain (SPF/DKIM/CNAME) under **Sending → Sender Domains**.
3. Create an API key with **Email send** permission under **Sending → API Keys**.
4. Put `SMTP2GO_API_KEY` (plus optional `SMTP2GO_SENDER`, `SMTP2GO_SENDER_NAME`, `SMTP2GO_AFFILIATE_LINK`) in `arab-templates/.env` and restart the server. Never put the key in front-end files.
5. In **⚙ Settings** fill sender name, verified sender email and Reply-To, then press **Test connection**.
6. In the invoice tab, add the customer email, issue the invoice, press **Email invoice**.
7. Errors are returned bilingually: missing key (400), invalid recipient/sender (400), SMTP2GO rejection (502), network failure (502).
